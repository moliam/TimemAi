# 模型接入点与请求分层

## 契约

Core 是唯一语义权威。链路：接入点配置 → 能力与配置校验 → 本次需求解析 → payload 映射 → 最终请求校验 → HTTP。

- `model_catalog`：模型事实、默认建议、协议约束、描述文件加载；不生成 payload。
- `model_requirements`：供应商/模型/协议身份、用户声明、来源及有效需求；不出现供应商 wire 字段。
- `reasoning`：H0 日常强度与 H1 自适应策略；不根据 URL、模型名称猜能力。
- `model_payload`：显式注册的 OpenAI Chat/Responses、智谱 Chat 映射；现有其他协议仅保留兼容路径。
- `model_api`：消息、工具、图像及请求组装；`model_transport` 在 HTTP 前执行 Core 校验。
- Host 持久化并转交配置；Web 编辑草稿、显示 Core 投影，不决定执行策略。

## 模板与身份

模板是建议来源，不是不可编辑的绑定。使用模板/无为同一入口。用户显式字段优先；移除模板保留值；不因 URL 或同名模型自动绑定供应商。供应商、模型、API 协议决定能力匹配；普通 API 与 Coding Plan 不混同，首批仅普通 API。显式修改与已知模型约束冲突必须显示错误，不静默改值。

协议入口由 `profiles[].default_base_url` 可选覆盖 `connection.default_base_url`，Core 投影解析后的地址。Web 切换协议时仅更新模板来源的 Base URL；手动地址（即使等于模板）不覆盖，移除模板停止联动。恢复入口及其说明仅在当前值与当前模板/协议组合的默认地址不同时显示，与字段来源无关；无已知默认地址时不显示。恢复模板地址使用当前协议并重新标记为模板来源；保存/重新编辑保留来源，旧配置按用户来源处理。模板选择器采用标签与下拉框并排的紧凑布局，窄屏不得横向溢出。

允许推理集合与日常强度分离。集合顺序来自模型声明；用户只选择子集，不通过排列改变强弱。未知集合不推测排序。H0 每次实际采用；H1 在压缩与周期复核时，从非 none 且不低于 H0 的集合取第二高，只有一项取该项；不降级。默认随日常推理开启，显式关闭保留。只有实际升级时投影 old/new，不展示思维内容。

协议下拉框按当前供应商/模型的 Core 能力投影筛选，不能把通用协议列表当作所有模型的能力。仅无能力声明的自定义服务保留通用列表；已有不兼容的显式协议保留为禁用项并标注不支持，阻止保存，不静默替换。OpenAI 供应商不提供 Anthropic Messages；网关协议转换不能推定为官方模型能力。

## 配置扩展

新模型只需新增版本化 JSON 描述，引用已实现适配器；不修改 Rust/TS 或编译。目录通过 `TIMEM_MODEL_CATALOG_DIR` 显式指定，在启动时读取；当前运行实例不热替换。限制文件大小、文件数与模型数，重复 ID、未知版本、未实现适配器或无效约束拒绝加载，不能声称支持。新增 wire 行为必须实现并测试适配器，禁止配置执行脚本或任意 JSON path 程序。

## 兼容与验证

旧配置缺失新字段仍可读取；未知旧模板 ID 降级自定义；加载不改写历史。兼容协议路径与新需求路径显式区分。测试覆盖纯策略、描述加载、payload 映射/篡改拒绝、旧配置恢复、真实本地 HTTP 工具往返、Web 编辑与隔离宿主浏览器。不使用付费远端 API，不重启开发实例。

本文为实施契约；完成情况以测试记录为准。
