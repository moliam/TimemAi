# Web UI Feature-Test Matrix

This document expands F32 in `docs/feature-test-management.md` into smaller
Web UI requirements. A Web UI change is not considered protected unless the
matching row below has at least one requirement-level test and, when relevant,
a host/runtime integration test.

| Requirement | Required behavior | Test evidence |
|---|---|---|
| Browser identity | The browser tab uses the same Timem logo as the Web sidebar, and the released Rust binary embeds and serves that image with the correct PNG content type. | `uses the Timem logo as the browser tab icon`, `embedded_frontend_assets_receive_browser_safe_content_types`, frontend production build. |
| Authenticated Web host | Web host binds to loopback by default, can explicitly bind publicly, serves embedded assets only after token/cookie authentication, accepts token or authenticated cookie for API/upload/WebSocket access, and does not leak token/referrer data. | `parses_basic_web_launch_options`, `public_web_launch_keeps_token_auth_and_reports_bind_mode`, `static_web_entry_requires_token_or_authenticated_cookie`, `rejects_ports_outside_the_local_web_range`, `generated_local_access_token_has_expected_entropy_shape`, `embedded_frontend_assets_receive_browser_safe_content_types`, `browser_responses_disable_referrer_leaks_and_remote_active_content`, `removes the access token from the visible URL while retaining the session credential`, `shows the runtime bind host and public-token mode from the server snapshot`, `scripts/web_public_runtime_smoke.sh`. |
| Session creation and naming | Users can create sessions, default names are `SessionN`, and user renames are reflected without changing worker identity. | `session_create_returns_the_complete_session_to_the_requesting_browser`, `unnamed_web_session_uses_session_name_while_worker_keeps_core_identity`, `uses session terminology consistently for the creation workflow`, `supports agent rename and a distinct animated working state`. |
| Per-session runtime profile | Each Web Session can carry model/protocol/URL/token/env overrides without mutating defaults. The header and Session list show the actual model only when the Session model service is configured; missing profile, blank model, or missing API key is shown as `未配置`, never as a misleading protocol default. Before send, incomplete configuration is explained with a direct Runtime-settings action. At send/model-call failure, missing keys, authentication failures, unavailable models, and network/service failures remain visible on the owning Session with actionable next steps; unknown provider reasons remain readable after credential redaction. Opening settings loads an existing API key through an authenticated request-scoped reply and presents the real value in a password input, masked by default; users can reveal, replace, or clear it, while snapshots and broadcast topics expose only whether a key exists. Applying one host default preserves unrelated unsaved drafts. | `session_creation_applies_independent_runtime_env_without_mutating_defaults`, `existing_session_api_key_can_be_updated_without_exposing_the_secret`, `session_api_key_update_is_rejected_during_an_active_turn`, `restored_session_keeps_cached_runtime_environment_without_exposing_it_to_web`, `runtime_update_propagates_to_existing_sessions_and_new_session_defaults`, `session_runtime_env_rejects_unknown_empty_and_invalid_values`, `creates sessions with independent runtime environment overrides`, `runtime setting drafts`, `session API key presentation`, `model display name`, `Session model configuration issue`, `model service issue presentation`, `keeps model configuration and service failures visible with actionable guidance`, `lets an existing session edit, reveal, and clear its API key without snapshot leakage`. |
| Session MCP management | Users can add stdio, Streamable HTTP, or legacy SSE MCP servers, inspect connection/tool status, enable them independently per Session, reconnect/edit/delete them, and use their discovered tools. The enable control uses a node-port metaphor: two separated gray outline nodes when disabled, blue filled nodes joined by a solid line when connected, and outlined nodes with a dashed link plus explicit cross when enabled but failed; connecting remains visually distinct without relying on color alone. Sensitive maps render as `****`; explicit reveal replies go only to the requesting authenticated socket. UI changes are deferred to a new-turn boundary; startup, restore, worker creation, and turn submission never wait on unavailable external MCP servers. Only a real model-visible tool change adds a `SYSTEM` prompt component. | `stdio_client_initializes_discovers_and_calls_tool`, `legacy_sse_client_discovers_and_calls_tool`, `curl_headers_split_before_sse_events_and_skips_interim_headers`, `stdio_notifications_do_not_extend_request_deadline`, `mcp_action_runs_through_protocol_registry_and_executor`, `mcp_server_error_becomes_action_evidence_instead_of_protocol_repair`, `mcp_capability_update_is_injected_only_when_tool_content_changes`, `queued_mcp_update_is_applied_before_the_next_user_turn_prompt`, `mcp_definition_is_mem_scoped_and_session_enablement_is_isolated`, `mcp_toggle_is_deferred_until_the_next_new_turn_boundary`, `session_create_and_restore_defer_unavailable_mcp_discovery_until_send`, `deleting_mcp_definition_removes_it_from_every_session`, `mcp_snapshot_redacts_secrets_and_edit_preserves_unmodified_values`, `legacy_sse_snapshot_redacts_sensitive_headers`, `stored_sessions_are_host_agnostic_and_sorted_by_recent_update`, `MCP editor transport drafts`, `MCP secret presentation`, `manages session-scoped MCP servers with accessible and responsive controls` (including synchronous duplicate-click suppression), frontend build. |
| Multi-session topic isolation | Core topics, worker activity, final answers, decisions, and cwd updates route only to the owning Session. | `concurrent_agent_topics_stay_in_their_own_session_and_wire_payload`, `real_concurrent_workers_route_final_topics_to_matching_web_sessions`, `mismatched_core_topic_is_not_forwarded_or_written_to_another_agent`, `applies a model response only to the session named by the core topic`, `applies a structured cwd update only to the matching session`. |
| Global worker role library | Creating or editing a Role appears immediately in every Session view while durable atomic persistence continues in the Host. The browser uses a stable client-generated role ID and command correlation, reconciles optimistic state with the authoritative library event, replays later pending mutations in order, and rolls back a rejected mutation without leaving a phantom Role. Role descriptions and the user message composer use a consistent non-resizable compact field with an in-field expand action; the composer matches its surrounding surface and uses a soft blue gradient border instead of a solid stroke, with coordinated attachment, send, and expand controls in both themes; the large editor synchronizes draft text without implicitly saving or sending, supports collapse/Escape, and can restore the pre-expand text through Cancel. | `worker_role_create_preserves_client_id_and_correlates_authoritative_event`, `worker_roles_are_global_grouped_persisted_and_render_exact_system_context`, `provides a coherent expanded editor for role descriptions and user messages`, `worker_roles_ui.test.ts`, `worker_role_theme.test.ts`, frontend production build. |
| Worker hierarchy and state | The UI can show primary/child workers while child worker details remain scoped to the owning Session turn. | `one_session_aggregates_primary_and_subworker_state_without_cross_finishing`, `child_context_worker_uses_its_owning_sessions_runtime_profile_and_env`, `expands each session into its scoped worker status list`, `keeps a matched agent working without changing unrelated sessions`. |
| Stop/cancel under human pressure | During active work the composer has one primary action: empty or whitespace-only input shows Stop, typing non-whitespace text switches it to Send, and clearing the draft restores Stop. Once cancellation starts the action remains disabled as `Stopping…` even if text is entered or completion state races ahead. Repeated Stop clicks are idempotent, repeated Send clicks cannot duplicate one draft, pending sends do not erase text typed during the send, draft text and pending send guards are isolated per Session, stale drafts/pending locks are pruned when snapshots swap out sessions, cancel stops all workers in the Session, stale Stop is harmless, and the next turn uses only the primary worker. | `cancel_stops_all_session_workers_and_next_turn_runs_only_primary`, `duplicate_cancel_commands_are_idempotent_for_one_active_turn`, `uses synchronous pending guards for rapid repeated browser clicks`, `guards one browser draft submission while preserving text typed during the pending send`, `keeps drafts and pending send guards isolated by session`, `prunes stale drafts and pending send locks when a snapshot swaps out sessions`, `does not send while cancellation is still in flight`, `keeps a human click storm bounded and session scoped`, `binds assistant-ui running state to the authoritative session lifecycle`, `switches one composer action between stop and send across typing and turn-state races`. |
| Send during active work | While Q1 is working, ordinary Send queues Q2 as a separate next turn. Q1's final answer remains attached to Q1 and visible before Q2 is submitted and rendered in a new user bubble. Only the explicit immediate-supplement action (Ctrl/Command+Enter or the queued row's `立即` action while Q1 is still working) may append to Q1. The Host rejects an ordinary `turn_submit` that races an active turn instead of silently converting it into a supplement. | `keeps ordinary working-session text as a separate next turn`, `keeps rapid ordinary sends during a working turn as separate next-turn submissions`, `turn_submit_during_an_active_turn_cannot_merge_into_the_current_turn`, `explicit_supplement_during_an_active_turn_stays_in_the_current_turn`, `manual_queue_send.test.ts`, queued-message ordering tests, frontend build. |
| Durable queued automatic sending | The pending-message area exposes an accessible sliding `自动发送` switch whose value changes only through an explicit user action. A Session automatically dispatches at most one queued message after its authoritative previous turn finishes normally with no stop reason. User cancellation, model/system errors, runtime rejection, disconnect, or local dispatch failure neither changes the switch nor triggers the next queued message; the queue remains available for manual sending. A ready state alone is never treated as successful completion. Each Session's preference and continuation eligibility are isolated, and the preference persists independently within the mem scope and synchronizes across tabs. Queued messages remain editable, reorderable, removable, and manually retryable. | `changes automatic sending only from an explicit user switch action`, `does not dispatch from ready state without a successful completion grant`, `routes background auto-dispatch by owning session rather than active UI session`, `holds the second message across committed ack until authoritative lifecycle unlocks its session`, `keeps other sessions dispatchable when one session is paused`, `releases a stuck send affordance only from the authoritative turn completion`, frontend build. |
| Explicit supplement boundary recovery | An explicitly requested supplement arriving after a cancel/completion race becomes a new task instead of failing with `active_turn_not_found`. If Q1's final answer becomes visible while an accepted supplement is still pending, Web closes Q1, preserves `final_answer1`, and resubmits the supplement as a distinct Q2 turn and user bubble; ordinary queued questions already use `turn_submit` and remain separate by construction. | `worker_option_returns_late_supplement_after_preserving_the_first_final_answer`, `final_answer_is_preserved_before_unconsumed_supplement_starts_a_new_turn`, `sends a new task after a cancelled active turn is marked finished`, `stale_supplement_after_cancel_completion_starts_a_new_turn`, `stale_supplement_after_cancel_consumes_pending_attachments_as_a_new_task`, `stale_topic_reply_after_turn_completion_is_ignored_without_host_error`. |
| Attachments | Users can upload, remove, and submit files. Submitted files move into the correct user entry, long names remain inspectable, and failed/racy paths do not drop files. | `pending_upload_moves_into_the_submitted_user_entry_and_is_not_reinjected`, `pending_attachment_removal_is_session_scoped_and_deletes_the_stored_file`, `duplicate_pending_attachment_removal_is_idempotent_for_the_same_session`, `failed_pending_attachment_file_removal_restores_the_session_entry`, `active_turn_supplement_consumes_pending_attachments_into_the_same_turn`, `failed_active_turn_supplement_does_not_drop_pending_attachments`, `lets users remove pending attachments without losing access to long file names`, `moves submitted files from the composer into a compact user attachment list`. |
| Inline decisions | Core/worker requests appear in the owning turn flow and replies route to the requesting worker without cross-session overwrite. | `child_context_worker_uses_its_owning_sessions_runtime_profile_and_env`, `stale_work_instruction_reply_during_new_active_turn_is_ignored`, `stale_topic_reply_after_turn_completion_is_ignored_without_host_error`, `queues concurrent decisions by session and request id without cross-session replacement`, `clears only the resumed workers decision within a shared session`, `uses an explicit session-created event and session-scoped inline decisions`. |
| Work instructions | AGENTS/CLAUDE decisions are not announced before acceptance, use timeout/default behavior, and stale replies are ignored. | `timem_web/tests/unit/web_host_tests.rs`, `does not turn work-instruction bookkeeping into user-visible activity`, `ask_mode_does_not_announce_work_instructions_before_user_acceptance`, `ask_mode_queues_the_first_turn_then_loads_work_instructions_after_matching_reply`, `ask_mode_decline_continues_the_turn_without_loading_work_instructions`, `ask_mode_rejects_a_mismatched_reply_without_releasing_the_pending_turn`, `stale_work_instruction_reply_during_new_active_turn_is_ignored`. |
| Current cwd display | Session list and composer show the authoritative cwd; a read-only `self_tool type=path` call cannot mutate it, and a Core cwd update applies only after Core reports the new value. | `timem_web/tests/unit/web_host_tests.rs`, `shows the tail of a long cwd while retaining short paths verbatim`, `successful_cwd_action_updates_only_its_session_and_reconnect_snapshot`, `real_worker_self_tool_path_call_is_read_only_for_web_session_cwd`, `shows the live session cwd in navigation and the composer footer`. |
| Turn process rendering | Free talk, progress, actions, repairs, context compact, and tool rows render inside the task process frame without noisy invented labels or stale running rows; completed work keeps a distinct compact title and ToolGen uses its own title. | Usage and context status | While a turn is running and after it finishes, token/cached/context stats stay attached to the correct Session and turn. | History and resume | Web restores recent chat, loads older history by pages, tolerates malformed records, and preserves task/supplement/approval semantics. | `stored_session_restores_after_web_host_restart_with_fresh_worker`, `history_page_command_loads_older_records_by_cursor`, `history_page_command_skips_malformed_records_without_breaking_cursor`, `restored_web_turns_follow_history_time_not_turn_id_lexical_order`, `restored_web_turns_preserve_user_entry_kinds`, `turn_user_entries_are_persisted_with_raw_text_and_semantic_kind`, `restores task, supplement, and approval user entries inside one turn`. |

When a Web UI feature changes, update this matrix in the same commit as the
code and tests. If a row cannot be fully automated, record the manual smoke in
`docs/manual-release-smoke.md`.
