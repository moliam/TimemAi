# Timem Application

`applications/timem` is the unified product composition root and owns the real
`timem` executable. The default mode assembles the local browser host;
`timem --shell` launches the terminal Interface in the same product. This
Application wires Core, Bridges, and Interfaces together. It is not a second
Agent runtime and must not become a reusable dependency of lower layers.

The Cargo package remains named `timem_web` for compatibility with existing
Cargo, CI, installation, and release commands:

```bash
cargo run -p timem_web --
cargo run -p timem_web -- --shell
```

## Dependency role

The Application currently assembles:

- `interfaces/shell` for terminal interaction;
- `bridges/http_websocket` for reconnectable browser delivery;
- `core/session` and `core/agent` for application-level worker/runtime wiring;
- the production bundle generated by `interfaces/web`.

Shell itself enters synchronous Turns through `bridges/in_process`; it does not
depend directly on Session or Agent. Reusable communication must stay in a
Bridge, reusable semantics in Core, and presentation in an Interface.

## Browser runtime

The default browser mode:

- binds only to `127.0.0.1` unless `--public` is explicit;
- chooses a port in `12345..=23456`, with `--port` selecting a fixed port;
- uses tokenless access only for loopback-local mode;
- generates a rotating access token for public browser/API/upload/WebSocket access;
- opens a browser only when a local graphical session is available;
- keeps model calls, prompt construction, memory, tools, and response parsing in Core.

A Web Session owns a runtime profile plus Context and Worker registries. Session
state and history use the shared Core Session store, allowing Web and Shell to
continue work in the same MEM. Secrets remain server-side and are redacted from
browser snapshots and durable browser command state.

## Frontend assets

The production frontend is built from `interfaces/web` and tracked under
`interfaces/web/dist`; this Application's `build.rs` embeds those files into the
Rust binary. Release users do not need Node or a separate frontend checkout.

Before changing browser behavior, read
[`interfaces/web/README.md`](../../interfaces/web/README.md) and
[`interfaces/web/module_boundary.md`](../../interfaces/web/module_boundary.md),
then run at least:

```bash
pnpm --dir interfaces/web test
pnpm --dir interfaces/web build
cargo test -p timem_web
```

Read [`module_boundary.md`](module_boundary.md) before changing Application,
Bridge, Interface, or Core ownership.
